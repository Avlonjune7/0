# 页面验证

## 验收范围

- 局部改动核对受影响入口。公共组件改动抽查代表页面。布局、响应式或交互变化在实际运行页面检查关键状态。出现新影响、失败、未解决疑点或用户要求时再扩大。
- 对照根 `DESIGN.md` 的适用范围，核对配色、字体、间距、布局、组件样式以及公共控件和主题用法。发现偏离已确认规范时修正实现。
- 全站统一核对全部目标页面的控件来源、用法和主题一致性。以约定范围的实际覆盖为完成依据，列出遗留位置、原因和未验收范围。
- Astryx 页面用项目版本的审查指引验收，例如 `astryx docs is-my-code-good`。Vue 页面按实际 shadcn-vue 配置和文档核对主题、状态及交互。线上故障用能重现问题的代表数据复核，必要时补关联回归测试。

## 浏览器

- 工具以用户指定为先。真实登录态的线上页面，或线上表单与接口的关联排查，优先读并使用 `browser-skill`。本地页面与独立测试优先用 `playwright-cli`。首选不可用时使用适合的已连接工具并说明原因。
- 同一页面只由一个工具控制。排查聚焦目标区域和相关接口字段，滚动问题在实际容器内验证。结束时清理本任务的会话。

## 性能与审查

- 用户要求优化、已有性能症状或改动涉及加载、请求、资源与渲染路径时测量。依据测量或明确症状定位，优先改善用户实际等待。全站优化选代表页面与关键交互建立基线，在相同数据和环境下复测。
- React 和 Next.js 的性能排查按问题使用 `vercel-react-best-practices` 的相关规则，全面审查才读完整汇编。其他技术栈使用项目工具和官方资料。
- 体验或视觉评审用 Impeccable 的 `critique`，技术质量专项用 `audit`。需要补查可访问性或 Web 实现时用 `web-design-guidelines`，同一次审查复用已获取的规则。
