# 页面验证

## 验收范围
- 局部改动核对受影响入口，公共组件改动抽查代表页面，布局/响应式/交互变化在实际运行页面核对关键状态；对照根 `DESIGN.md` 检查样式与公共控件用法。
- Astryx 页面用项目版本指引验收（如 `astryx docs is-my-code-good`）；Vue 页面按 shadcn-vue 配置核对主题与交互。

## 浏览器分工
- 用户指定工具优先；否则：真实登录态页面或线上表单/接口关联排查优先 `browser-skill`，本地页面与独立测试优先 `playwright-cli`。
- 同一页面只由一个工具控制，滚动问题在实际容器内验证，结束时清理本任务会话。

## 性能与评审路由
- 有性能要求、明确症状或改动加载/渲染路径时先测量建基线，再优化并同条件复测。
- React / Next.js 性能排查按问题按需读 `vercel-react-best-practices` 对应规则，不整本加载。
- 视觉/体验评审用 `impeccable` 的 `critique`，技术质量与无障碍专项用 `audit`。外部技能不可用时直接降级并说明缺口，不反复查找。
