# 组件与设计系统

## 定位与复用

- 先确认技术栈、统一组件入口和相关调用。入口可以是项目公共目录、共享包或组件库官方导出。先按功能和交互查已有能力，再查所用版本的文档或 CLI。
- 复用符合需求的公共 UI 能力，包括表单、展示、反馈、浮层、导航、布局、焦点、键盘、滚动锁定、拖拽和加载、空、错误、禁用状态。缺口确认后在统一组件层最小扩展，并说明原因。
- 控件外观通过组件 API、公共变体或主题 Token 调整。页面使用 Flex、Grid 和项目间距约定编排。禁止在页面级覆盖重做公共控件。
- 局部修改限于相关组件、统一入口和受影响调用。组件迁移、整体统一或确认存在混用时扩大核对范围。混用现状不足以确认迁移目标，先核对项目书面约定和用户已确认的目标，本次改动向已确认体系收敛。

## 已选体系的接入

- Astryx 接入前确认 `react` 和 `react-dom` 满足 React 19+ 与所选版本的 peer dependencies。低版本先评估升级影响。实现遵循 Astryx 技能和项目所用版本的文档；项目采用 Astryx 时，允许其初始化或升级工具维护自身生成的项目指引区块。
- shadcn-vue 的 Reka UI 底层交互封装在统一组件层。页面和业务组件通过统一入口使用，旧项目以实际依赖版本为准。
- 框架升级或整体替换先评估兼容性和成本，再按已确认的迁移范围实施。React 复杂组件设计或重构可用 `vercel-composition-patterns`。

## 设计规范

- 项目根目录只维护一份 `DESIGN.md`。商城、后台等界面在同一文件分别标明适用范围。后续改动按该项目文件执行。
- 缺少 `DESIGN.md` 时，先复用已确认的设计决定，再按产品用途、受众和信息密度从 `D:\code\awesome-design-md-main\design-md` 选择模板（若该目录不存在则直接按项目需求起草）；将适用的配色、排版、间距和布局映射到项目现有组件与主题 Token，把结果及模板来源写入根 `DESIGN.md`。产品事实和验收条件留在项目既有的产品与规格文档。
- 后台和工具界面偏好简洁、专业、高信息密度，搜索框默认无内阴影。阅读场景以舒适清晰为主。品牌和展示页面按受众决定视觉表达。用户明确的品牌与设计要求优先。
- 用户要求设计、重设计、体验规划、精修或视觉与交互评审时，使用 Impeccable 的对应流程。精修延续既有视觉方向。重设计按授权调整同一份 `DESIGN.md` 的相关范围。普通界面实施按既有设计和组件体系推进。
- 所需技能或工具不可用时，复用项目能力和对应版本的官方资料，说明由此产生的验证缺口。
