# 组件与设计系统

## 复用与边界
- 先确认项目技术栈与统一组件入口（公共目录、共享包或组件库导出），优先复用已有公共控件与状态处理；确有缺口在统一组件层最小扩展并说明原因。
- 外观通过组件 API、公共变体或主题 Token 调整，布局用 Flex/Grid 与项目间距约定；**禁止在页面级覆盖重做公共控件**。
- 遇组件混用时不臆断迁移，先按书面约定或用户确认的目标收敛。

## 默认体系接入
- **Astryx（React）**：接入前核对 `react` / `react-dom` 满足 React 19+ 与 peer dependencies，低版本先评估升级影响；遵循所用版本文档，允许其初始化/升级工具维护自身生成的项目指引区块。
- **shadcn-vue（Vue）**：Reka UI 底层交互封装在统一组件层，页面通过统一入口调用。

## `DESIGN.md` 与设计路由
- 项目根只维护一份 `DESIGN.md`（商城、后台等多场景在同一文件分范围注明）。引入新体系或修改已有 `DESIGN.md` 必须先获用户明确同意。
- 已有视觉体系但缺 `DESIGN.md` 时，从现有页面、公共组件和主题整理；新项目或授权重选型时，先按产品用途与信息密度从 `D:\code\awesome-design-md-main\design-md` 列出 2–3 个候选模板并仅附在线预览链接（取自各模板 `README.md` 的 `getdesign.md` 链接）由用户确认，待确认后用 shell 命令整份复制到项目根作为底稿（禁止读完由模型整篇重写），再记录来源并按实际局部裁剪（模板目录缺失时按需求起草）。
- 将模板文字角色与组件映射到公共样式、主题 Token 或变体；产品事实与业务 AC 留在规格文档，不混入 `DESIGN.md`。
- 风格偏好：后台/工具界面简洁、专业、高信息密度，**搜索框默认无内阴影**；阅读页舒适清晰；展示页按受众决定。用户明确要求优先。
- 设计、重设计、精修或体验评审走 `impeccable` 对应流程；所需技能不可用时降级复用项目与官方资料并说明缺口。
