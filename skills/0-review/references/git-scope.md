# 确定 Git 比较范围

按用户要求选定目标树和比较起点，固定提交的 SHA，并告知所用的比较语义。使用当前可用的 refs 或 PR 元数据核对目标，在基线确实无法推断时只询问会改变结论的缺失信息。

没有 Git 仓库或版本历史可用时，直接审查用户指定的源码文件或快照，并注明没有历史差异可供核对。

| 用户目标 | 比较方式 |
| --- | --- |
| 当前未提交变更、工作区 | 以 `HEAD` 为默认基线，分别读索引、工作区与未跟踪文件。尚无首次提交时，用空树作为暂存变更的比较起点。 |
| PR、分支相对基线引入的变更 | 固定所审 base 和 head，取 `git merge-base <base> <head>`，再比较共同祖先到 head。优先遵循用户所指 PR 的实际变更范围。 |
| 明确的提交端点或单个提交 | 直接比较两个端点。单个普通提交与其父提交比较，首提交与空树比较。合并提交按明确指定的父线或项目约定审查，报告所用父线。 |
| 从指定基线审到当前工作区 | 依据用户要求比较基线到 `HEAD` 的已提交变更，并单独纳入索引、工作区和未跟踪文件。报告区分三类未提交内容与提交范围。 |

工作区审查使用 `git status --porcelain=v1 --untracked-files=all` 枚举，`git diff --cached --` 查看暂存变更，`git diff --` 查看未暂存变更，并直接读取范围内的未跟踪文件。两个 diff 各自保留证据，同一路径的两次改动可能在合并差异中抵消。用 `git ls-files --others --exclude-standard` 提取未跟踪路径时，仍由审查者核对文件内容。用户明确限定暂存区时，仅审索引内容。

读取与所审状态对应的版本。固定提交用 `git show <提交>:<路径>`，索引用 `git show :<路径>`，工作区用实际文件。混合暂存和未暂存变更时，核实结论属于索引、工作区最终状态或两者。范围中的文件无法获取、存在未合并项或审查期间被修改时，标明受影响的覆盖及证据，必要时仅重读相应部分。
