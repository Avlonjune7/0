# 0-setup

让后续会话快速定位运行入口、模块边界、规格、决策和任务，并保持文档与源码一致。沿用项目既有语言要求。

## 模式

未给路径时用当前工作目录；目标不明确先定位。默认**轻量接入**：

- **轻量接入（默认）**：复用或接入本地 Git，补齐 `AGENTS.md`、`docs/workflow.md`、根 `README`；只读配置、入口、契约和已有文档，不全量扫描源码。
- **深度建档**：明确要求全库模块文档或接手缺少说明的大中型代码库时启用，按 [deep-scan.md](references/deep-scan.md) 执行。
- **漂移核对与同步**：检查或同步过期文档时，按 [doc-sync.md](references/doc-sync.md) 执行，跳过初始化与 Git 接入。

说明范围后直接写入可逆文档；业务代码、依赖、提交、推送、部署和远端接入均不默认执行。

## 1. 识别现状

- 先运行 [scan_project.py](scripts/scan_project.py)（`--help` 查看参数）列出文档、配置和候选源码目录，再按 [discovery.md](references/discovery.md) 核对适用指令、已有改动和项目入口。
- 完整初始化时缺少本地 Git、仓库边界存疑或要求接入远端，读 [git-setup.md](references/git-setup.md)；已有仓库和 worktree 直接复用。
- 列出工作清单：模式、需补齐的文档、复用的已有来源、尚不能确认的事实。已有规格、计划、架构和 tracker 原样复用，不为套用默认布局而改名或搬迁。

## 2. 约定布局

只创建有内容的文件。文档职责、模块文档写法和 `DESIGN.md` 规则见 [documentation.md](references/documentation.md)。

```text
project/
├── AGENTS.md            # 项目约束和按需读取指针
├── README.md            # 介绍、运行入口、模块导航
├── DESIGN.md            # 唯一 UI 规范，无 UI 不创建
├── docs/
│   ├── workflow.md      # 文档位置、状态、读取与更新时机
│   ├── decisions.md     # 决策日志，有实际决定时再建
│   ├── specs/           # 有实际规格时再建
│   └── tasks/           # 有实际复杂任务时再建
└── 实际代码目录/
    └── 实际模块/README.md  # 仅深度建档或复杂模块需要时创建
```

- 代码目录沿用现状。已有 `AGENTS.md` / `CLAUDE.md` 按现有分工维护；只有 `CLAUDE.md` 时复用它；两者都没有时创建 `AGENTS.md`。
- `AGENTS.md` 写一段简短指针，说明何时读 workflow、决策日志、`DESIGN.md` 和模块说明。其他 0-* 技能依靠这段指针定位资料。
- 用 [workflow 模板](assets/workflow.md) 记录规格与任务位置、tracker、状态约定和决策日志格式。存在 GitHub remote 不等于项目使用 GitHub Issues。尚未创建的目录写为约定路径，不生成虚假链接。

## 3. 建立事实依据

- **轻量接入**：只写已核实的入口与边界，不推测未读的实现细节。
- **深度建档**：完整阅读将要描述的模块；阈值和分块方式见 deep-scan.md。
- 读取受限、依赖缺失或调查失败时，继续独立部分，并把对应范围标为未完成。
- **空项目**：只记录用户已确认的目标；缺少关键用途时询问，不虚构技术栈、命令、模块或进度。

## 4. 写入文档

- 模块文档参考 [模块模板](assets/module-readme.md)，删去不适用的章节和提示，不为每个目录机械生成 README。
- 原地修改相关章节，保留人工说明与已确认决策；规则与代码不一致时记录差异与证据，不把现状当需求。
- 只写配置变量名、用途与来源；不撰写新需求/任务，不建空 `specs/`、`tasks/` 或无决定时的决策日志。

## 5. 核对并交付

1. 所述职责、接口和命令可追溯到实际配置或实现；区分"配置存在"与"实际运行通过"（纯文档改动不启服务、不跑全套测试）。
2. 用 [check_links.py](scripts/check_links.py) 批量核验本地链接，清除模板提示、虚构命令和重复规则。
3. 查看 diff 确认改动限于文档与约定的 Git 初始化/忽略规则；项目无变化时再次运行应无修改。

交付不超过 8 行：采用的模式、新建/更新项、核对方式、遗留缺口。完成即停止，不自动进入规划或开发。
