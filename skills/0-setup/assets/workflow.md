# 项目工作约定

> 写作提示：用已发现的实际路径替换下面说明，复用现有约定，省略不适用项。不要将此提示或空占位复制到项目。

## 文档与任务位置

| 信息 | 权威位置 | 何时读取或更新 |
| --- | --- | --- |
| 项目运行与导航 | 根 README 或已有入口 | 启动项目、运行方式改变时 |
| 功能规格 | 实际规格位置；不存在时写约定路径 | 改变业务行为前读取，批准变更后同步 |
| 决策日志 | docs/decisions.md 或已有 ADR 位置 | 规划和实施前读相关条目；做出影响后续的决定时追加 |
| 任务记录 | 实际 tracker 或本地任务位置 | 复杂任务规划、进度变化或交接时 |
| UI 规范 | 实际 DESIGN.md；无 UI 则省略 | UI 改动前读取，规范变更需用户同意 |
| 模块说明 | 实际模块文档位置 | 修改对应模块前读取，契约改变后同步 |

## 状态与编号

- 规格：`草案` → `已批准`。中等以上任务经金鱼评审和用户批准后再实施。
- 任务：计划中、进行中、受阻、已完成。
- 验收条件编号为 `AC-1`、`AC-2`…，验证记录和评审意见按编号引用。

## 决策日志格式

每条追加到文件末尾，2–4 行：

```text
## YYYY-MM-DD 决定标题
- 决定：……
- 原因：……（备选及放弃理由）
- 影响：相关规格、模块或 AC
```

推翻旧决定时新增一条并引用旧条目，不改写历史。

## 任务约定

记录本项目实际的任务管理方式和命名规则。未采用外部 tracker 时，复杂任务默认在 docs/tasks 下每个任务一个文件，文件名包含日期与主题。小改不为记录流程新建任务文档。

## 维护边界

规格描述已认可的功能要求，模块说明描述当前实现。两者不一致时记录依据并处理差异，不自动把实现当成正确需求。按本次改动同步受影响文档，保留已有有效内容；验证记录区分未运行、实际通过和实际失败。
