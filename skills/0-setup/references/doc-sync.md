# 文档漂移核对与同步

仅在用户要求集中检查文档与当前源码的一致性、核对文档漂移或修订过期说明时读取。随功能交付的局部文档更新由 `0-build` 顺手处理。

## 范围与授权

- 按用户指定的文档、模块或变更确定范围，未指定路径时从当前项目定位。先读适用项目指令、`docs/workflow.md` 或等效约定；涉及 UI 时读取根 `DESIGN.md` 按适用范围核对。
- 检查、一致性核对和漂移报告请求只读；同步或修订请求授权原地修正文档中证据充分的现状描述，写入限于文档。发现实现缺漏时报告对应代码位置，不擅自改业务代码。仅按用户要求保存独立报告。

## 核对证据与覆盖

- 列出范围内文档、适用版本和对应实现入口，区分已认可要求、现状说明、草案和历史记录。任务状态只按已有记录与可核实的完成证据更新。
- 从文档的路径、符号和断言追到具体实现（入口、调用路径、配置、Schema 或测试），核对职责、接口、约束、副作用和命令仍成立；同时从实现反查文档承诺覆盖的范围，查找遗漏的关键行为。区分环境配置、代码可证行为和已实测结果；查不到的证据记作覆盖缺口。

## 处理差异

- **说明过期**：有明确证据时按授权原地更新具体段落，保留人工说明、历史版本和无关修改；重复内容优先指向权威来源。
- **实现与已认可要求冲突**：保留要求，记录预期、实际与双方证据位置，交由用户裁决改代码还是改规格（同样适用于 `DESIGN.md` 与现有 UI 冲突）。变更认可要求须有明确决定。
- **草案、冲突或证据不足**：保持原状，注明未决事项与待核查依据，完成其余可确认部分。

## 验证与交付

- 核对范围内文档与内部链接；检查本地路径和常见标题锚点优先使用 [check_links.py](../scripts/check_links.py)（`--help` 查看参数）。尚未建立的目标用文字说明。
- 用 diff 核验修改段落与证据一致，变更限于授权文档并保留他人编辑。相同范围和证据再次运行时，现有内容已成立就直接交付结论，避免重写段落、刷新时间戳或追加重复报告。
- 交付检查范围、已修订项、仍存在的差异与证据及未覆盖部分。**一致部分仅给出覆盖范围摘要，详细清单聚焦差异、冲突与缺口，不逐项复述一致内容。**
