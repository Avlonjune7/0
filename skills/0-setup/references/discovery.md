# 现状调查

只调查用户指定项目或子目录。子目录任务可读上级规则与必要依赖，但写入保持在授权范围；已有根级约定不因局部文档任务重写。

## 建立入口

1. 确认路径和仓库边界；若是 Git 仓库，记录当前分支、未提交改动和相关文件 diff。文档中已有未提交内容不代表可以覆盖。
2. 读取适用的 AGENTS.md、CLAUDE.md、根 README 与已有文档入口。遇到多份规则按适用范围判断，不把它们合并为一份新全局规则。
3. 用文件列表和构建配置识别技术栈、模块、测试入口、迁移与接口定义。版本、命令从 lock、manifest、task runner 等权威文件查明，不凭框架名称猜测。
4. 查找已存在的规格、架构、进度、设计规范、术语表和任务管理说明，建立路径映射。不能只找默认文件名。

## Git 接入

完整项目初始化默认确保本地 Git 可用；用户明确仅做文档、指定局部目录或要求不初始化 Git 时，保持该范围。

1. 用 `git -C <项目目录> rev-parse --show-toplevel` 判断现有仓库边界，兼容 `.git` 文件形式的 worktree。项目属于上级仓库时复用其版本管理，不创建嵌套仓库；边界与用户指定的独立项目冲突时先明确归属。Git 命令失败时查明原因，权限、安全目录或仓库损坏不能当成“无仓库”。
2. 确认独立项目没有仓库后，执行 `git -C <项目根> init -b main`。已有分支、历史、暂存区和远端保持原状；不为初始化修改全局 Git 身份、重置工作区或创建首次提交。Git 未安装时报告缺口并继续独立的文档工作，不宣称 Git 接入完成。
3. 根据实际技术栈补齐根 `.gitignore`，保留已有规则与例外，优先忽略依赖、构建缓存、本机环境文件和明确的运行数据，保留可分享的示例配置。用 `git check-ignore` 核对代表路径。不要批量暂存文件；敏感文件已被跟踪时报告路径，不展示内容，不自动删除历史或取消跟踪。
4. 检查已有远端，区分本地版本管理、远端仓库与任务 tracker。未要求远端时本地仓库即可完成，任务记录沿用项目约定。用户要求远端接入时复用已明确的地址；缺少地址，或创建新仓库所需的账户、名称、可见性时，只询问缺失决定。按授权添加远端，不覆盖同名远端；创建远端与公开代码不能从普通初始化请求推定。配置地址不代表已连接成功，用 `git ls-remote` 或对应平台工具核实可访问性，不自动拉取合并、提交或推送。连接失败时报告本地已完成、远端受阻。
5. 在工作约定中只记录会影响后续工作的版本管理方式和已确认远端入口，不复制凭据或动态 Git 状态。验收时核对仓库根、状态、忽略规则及本次授权的远端；新仓库无提交不是失败，也不能记为已有可回退的提交基线。

## 读取范围

跳过第三方依赖、生成代码和构建产物、缓存、Git 对象及无关大媒体；尊重项目忽略规则。配置优先读变量名与示例文件，不扫描真实 secret 文件。若关键行为只在未获访问的来源中，记录缺口。

全项目初始化需先列出第一方模块并逐个覆盖；按实际模块切分阅读批次，不把顶层目录摘要冒充全项目分析。模块内部按契约与入口、关键实现、依赖和测试阅读。只读过入口时，不描述尚未追踪的完整链路。

调查笔记记录在当前工作上下文或临时工作区，不给项目新增永久日志。每个模块至少收集：

- 职责与关键入口：实际文件路径和符号。
- 对外接口、调用方和关键依赖；明确引用的是本地还是外部实现。
- 约束在哪一层维护；副作用涉及数据库、文件、网络或后台任务中的哪些部分。
- 相关测试与可用验证命令；是否运行以及实际结果。
- 已有文档冲突、缺少信息和未覆盖部分。

## 分块与独立并发阅读

1. 列出本次范围内的第一方源码与相关配置、契约、测试，记录版本或工作区状态。`scripts/scan_project.py` 只提供候选目录和路径信息，不解析定义、不证明阅读覆盖；结果截断时补全清单，也要核对扩展名识别和默认忽略目录是否遗漏项目实际源码。
2. 用项目已有符号索引、解析器或定向搜索定位函数、类、方法的起止位置，再按完整定义边界组块，目标每块约 1,500 行。小文件可在同模块内合并；大类可沿完整方法边界分块并提供类声明、字段和共享上下文。单个不可再按定义边界拆分的函数超过目标时整块读取并注明超长，不在函数体中间硬切或截断。导入、顶层初始化和定义之间的代码也须覆盖。同一逻辑块可由同一代理连续分页取回；工具输出截断时补读缺失区间，不把一次调用的输出上限当作完整阅读。
3. 在当前上下文或临时工作区维护块清单：模块、文件、行范围或符号范围、相关共享上下文、读取状态与报告来源。行号绑定本次读取版本；文件发生变化时重新核对受影响块。每个范围内文件必须被完整覆盖或明确列为未读取，不以约 1,500 行作为只读文件前段的上限。
4. 为每块启动无历史的只读子代理；Codex 使用 `fork_turns: "none"`。交给它实际项目路径、适用约束、分配范围、导入和定义索引、相关契约、适用 README 或等效文档路径与章节、返回要求，不传主会话推测。有多个可独立块时必须并发，整个任务最多同时 6 个阅读子代理，不含主会话；超过上限排队。所有阅读任务由主会话统一调度，阅读代理不再自行派生子代理，也不写文档。只有一个块时使用一个子代理，不人为凑数量。
5. 每块返回已完整读取的范围、职责、接口、约束、副作用、重要调用依赖、配置或测试入口，以及未确认项；事实注明路径与符号。跟踪必要依赖，新增阅读范围交由主会话补入清单，避免多代理重复探索。主会话明确各块负责核对的文档章节，跨模块断言在汇总后核对。已有 README 与源码的差异一并返回；文档中的已批准需求不能被实际错误行为覆盖。
6. 主会话按模块合并报告、解决交叉依赖和冲突，核对覆盖清单后，先写已确认的叶子模块，再逐层写父级及根文档。父级依据已核实的子模块事实形成导航，不从目录名猜测架构。未完成模块只报告缺口，不生成虚构契约。

启动失败、超时或仅返回部分范围的任务不能计为完成；主会话记录已覆盖范围并结束失效任务，必要时只为缺失或版本已变的范围重新排队，仍未完成时列明缺口，不进行无界重试。

宿主可用并发额度不足 6 时按实际额度排队，并说明限制；没有独立子代理能力时报告源码调查受阻，可完成不依赖该调查的文档入口工作，但不能声称满足独立阅读或完整初始化。没有源码的空项目沿用主技能的空项目流程，不派空任务。

## 需要用户决定的情况

查文件能解决的事实由代理查明。只在重要目标缺失、互相冲突的权威约定、确需改变既有文档布局或工作范围时提问。询问期间继续不依赖该答案的调查和文档工作；不因普通初始化反复请求相同授权。
