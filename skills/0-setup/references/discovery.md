# 现状调查

只调查用户指定项目或子目录。子目录任务可读上级规则与必要依赖，但写入保持在授权范围；已有根级约定不因局部文档任务重写。

## 建立入口

1. 确认路径和仓库边界；若是 Git 仓库，记录当前分支、未提交改动和相关文件 diff。文档中已有未提交内容不代表可以覆盖。
2. 优先调用 [scan_project.py](../scripts/scan_project.py) 快速列出已有文档、常见配置和候选源码目录，留意截断标记。
3. 读取适用的 AGENTS.md、CLAUDE.md、根 README 与已有文档入口。遇到多份规则按适用范围判断，不把它们合并为一份新全局规则。
4. 用文件列表和构建配置识别技术栈、模块、测试入口、迁移与接口定义。版本、命令从 lock、manifest、task runner 等权威文件查明，不凭框架名称猜测。
5. 查找已存在的规格、架构、进度、设计规范、术语表和任务管理说明，建立路径映射。不能只找默认文件名。

## 读取范围

跳过第三方依赖、生成代码和构建产物、缓存、Git 对象及无关大媒体；尊重项目忽略规则。配置优先读变量名与示例文件，不扫描真实 secret 文件。若关键行为只在未获访问的来源中，记录缺口。

- **轻量接入（默认）**：聚焦运行入口、构建与测试配置、对外契约、关键目录边界与已有文档核对，按需最少读取，不把顶层目录名猜测成完整实现细节。只读过入口时，不描述尚未追踪的完整链路。
- **深度建档（按需）**：列出第一方模块并逐个覆盖；模块内部按契约与入口、关键实现、依赖和测试阅读。源码量超过单块阈值时，按 [分块与独立并发阅读](deep-scan.md) 调度。

调查笔记记录在当前工作上下文或临时工作区，不给项目新增永久日志。需要描述某个模块时，至少收集：

- 职责与关键入口：实际文件路径和符号。
- 对外接口、调用方和关键依赖；明确引用的是本地还是外部实现。
- 约束在哪一层维护；副作用涉及数据库、文件、网络或后台任务中的哪些部分。
- 相关测试与可用验证命令；是否运行以及实际结果。
- 已有文档冲突、缺少信息和未覆盖部分。

## 需要用户决定的情况

查文件能解决的事实由代理查明。只在重要目标缺失、互相冲突的权威约定、确需改变既有文档布局或工作范围时提问。询问期间继续不依赖该答案的调查和文档工作；不因普通初始化反复请求相同授权。
