# Git 接入

仅在完整项目初始化且当前目录缺少 Git 仓库、仓库边界存疑或用户明确要求接入远端时读取。用户明确仅做文档、指定局部目录或要求不初始化 Git 时，保持原范围。

1. 用 `git -C <项目目录> rev-parse --show-toplevel` 判断现有仓库边界，兼容 `.git` 文件形式的 worktree。项目属于上级仓库时复用其版本管理，不创建嵌套仓库；边界与用户指定的独立项目冲突时先明确归属。Git 命令失败时查明原因，权限、安全目录或仓库损坏不能当成“无仓库”。
2. 确认独立项目没有仓库后，执行 `git -C <项目根> init -b main`。已有分支、历史、暂存区和远端保持原状；不为初始化修改全局 Git 身份、重置工作区或创建首次提交。Git 未安装时报告缺口并继续独立的文档工作，不宣称 Git 接入完成。
3. 根据实际技术栈补齐根 `.gitignore`，保留已有规则与例外，优先忽略依赖、构建缓存、本机环境文件和明确的运行数据，保留可分享的示例配置。用 `git check-ignore` 核对代表路径。不要批量暂存文件；敏感文件已被跟踪时报告路径，不展示内容，不自动删除历史或取消跟踪。
4. 检查已有远端，区分本地版本管理、远端仓库与任务 tracker。未要求远端时本地仓库即可完成，任务记录沿用项目约定。用户要求远端接入时复用已明确的地址；缺少地址，或创建新仓库所需的账户、名称、可见性时，只询问缺失决定。按授权添加远端，不覆盖同名远端；创建远端与公开代码不能从普通初始化请求推定。配置地址不代表已连接成功，用 `git ls-remote` 或对应平台工具核实可访问性，不自动拉取合并、提交或推送。连接失败时报告本地已完成、远端受阻。
5. 在工作约定中只记录会影响后续工作的版本管理方式和已确认远端入口，不复制凭据或动态 Git 状态。验收时核对仓库根、状态、忽略规则及本次授权的远端；新仓库无提交不是失败，也不能记为已有可回退的提交基线。
