# 文档职责与维护

## 单一来源

| 位置 | 内容与更新条件 |
| --- | --- |
| 根 README | 项目介绍、如何启动、配置入口、模块导航；运行方式或入口改变时更新 |
| AGENTS.md / 已有规则入口 | 项目特有约束和按需读取指针；规则改变时更新，不复制个人全局规则与技能正文 |
| docs/workflow.md 或已有等效说明 | 各类文档与任务位置、tracker、状态约定、读取与更新规则；工作约定改变时更新 |
| DESIGN.md | 根目录唯一 UI 设计规范；按下面的设计规则处理 |
| 模块 README 或已有等效文件 | 当前实现的职责、接口、约束、依赖、副作用和验证入口；对应实现改变时更新 |
| specs 或已有规格位置 | 已认可的功能行为、业务规则和带编号的验收条件；此技能只定位和引用，不从代码自动生成已批准规格 |
| decisions.md 或已有 ADR 位置 | 跨会话需要记住的关键决定及原因，只追加不改写；此技能只约定位置和格式，不虚构决定 |
| tasks 或已有任务位置 | 某次复杂任务的范围、计划、进度、验收结果；此技能只建立约定，不创建虚构任务 |

已存在 PRD、ARCHITECTURE、PROGRESS、PLAN、数据库或接口文档时保留其职责，不强制迁移到默认布局。数据库结构、接口 Schema 和命令配置直接引用实际定义，避免手抄完整字段表或脚本列表。

## 根入口与接入约定

规则入口添加或更新一个简短的项目文档指针，说明何时读 workflow、决策日志、UI 规范与模块说明。优先更新已有等效段落，保留周围内容。若已有规则已经充分指向这些资料，保持不变。

workflow 记录实际路径及维护责任；没有外部 tracker 时，默认复杂任务在 docs/tasks 下每任务一文件，文件名包含可区分的日期与主题。状态与编号按 workflow 模板；已有状态或 tracker 映射优先沿用。仅有远端 Git 仓库时不自动改成远端任务管理，不调用 API 建标签或任务。

specs 是长期当前规格，tasks 是某次改动记录。完成后任务标记结果并保留必要证据，不默认删除，也不默认复制归档。后续开发同步本次受影响文档，无需每次重新运行 setup。

## 根 README 写法

- **一屏看懂定位**：标题 + 一句话说明解决的问题与当前运行形态，只描述现状，清理已废弃方案与历史过渡说明。
- **最短可用路径**：快速开始只保留当前主用环境的最小安装、启动、构建与验证步骤；长教程外链到独立部署/运维文档，不在 README 重复抄写。
- **配置与导航**：环境变量只列名称、默认值与用途并指向示例文件；提供精简目录结构、核心入口或接口速查及文档导航。
- **篇幅与层次**：常规项目控制在 120–180 行左右；高频入口、流程图与总览表放上半屏，低频参数、脚手架详情与来源对照下沉到底部或用 `<details>` 折叠。

## UI 设计规范

- 有 DESIGN.md：读取其适用范围，只建立正确引用。初始化文档不是变更已批准设计的授权。
- 无 UI：不创建 DESIGN.md。
- 有 UI、缺规范：先核对项目规则、已有设计决定、统一组件入口与 Token。能够忠实整理已确认规范时写入根 DESIGN.md，记录依据与范围，不把偶然样式当作批准标准。
- 需要新选型或现有样式冲突：按用户适用的个人/项目设计约定处理；按需读取可用的个人设计指引。缺少决定时询问关键选项，同时完成其他文档。未确认部分列为缺口，不安装组件库、不改 UI、不编造已确认体系。
- 技术方案使用现有架构/规格位置，不能另建 design.md 与 DESIGN.md 混用。

## 模块文档

按包、业务模块或明确责任边界生成。父级概述职责与依赖并链接子模块；子模块解释自己的契约，不重复父级介绍。没有实际内容的小目录不创建 README。

已有 README 含人类说明时增量补充；已有独立模块文档时直接引用，不再创建竞争副本。具体事实附近使用仓库内相对链接与准确符号名，避免仅靠易过期的行号。只有追踪到实现的约束才能写为当前行为。

输出模板是取材提示，不是强制章节清单。没有对外接口或副作用时可简述或省略，无法确认时明确缺口；不要为填满章节捏造内容。所有内部链接相对所在文档解析，目标不存在时写为普通路径约定。
