# 接入调查、文档规范与深度建档

## 1. 现状调查
- 仅调查授权目录；Git 仓库先记录分支、未提交改动与 diff，不覆盖文档中的既有未提交内容。
- 从 lock、manifest、task runner 等权威文件查明技术栈、版本与命令，不凭框架或目录名猜测。
- 跳过第三方依赖、构建产物、缓存、Git 对象及真实 secret 文件（配置只读示例与变量名）；查已有规格、架构、设计规范与 tracker 映射，不局限于默认文件名。
- 调查笔记留在会话或临时工作区，不新增永久日志。仅在重要目标缺失、权威约定冲突或确需改既有布局时询问，询问期间继续独立部分。

## 2. 文档职责与写法
- **单一来源**：根 README 管定位、启动、配置入口与模块导航；`AGENTS.md` / 既有规则入口只放项目特有约束与按需指针（不复制个人全局规则）；`docs/workflow.md` 管文档/任务位置与状态约定；模块 README 管当前实现契约；`specs` 管已认可行为（不从代码反推生成）；`decisions.md` 追加记录关键决定；`tasks` 记录复杂任务。已有 PRD/ARCHITECTURE/Schema 直接引用，不搬迁、不手抄完整字段表。
- **根 README**：一屏看懂定位与现状（清理废弃方案）；快速开始仅留当前主用环境的最短安装/启动/验证路径；环境变量只列名称、默认值与用途并指示例文件；常规控制在 120–180 行，低频详情下沉或用 `<details>` 折叠。
- **UI 规范（`DESIGN.md`）**：根目录唯一；无 UI 不创建；已有规范只建引用；缺规范但有成熟样式时按已确认事实整理；需新选型或样式冲突时按个人/项目设计约定询问关键选项，不擅自装库或改 UI。技术方案勿另建 `design.md` 与之混用。
- **模块文档**：按包或明确责任边界生成，小目录不建 README；父级概述职责与导航，子级说明接口、约束、依赖、副作用与验证入口；事实附仓库相对路径与准确符号名，少依赖易过期行号。

## 3. 深度建档（大中型代码库按需）
仅在用户明确要求全库模块文档建档，且第一方源码较大（超约 2,000 行）时启用；小型项目直接由主会话完整阅读。

- 以 [scan_project.py](../scripts/scan_project.py) 为起点核对完整源码清单（留意截断与扩展名遗漏），按完整定义边界（模块/类/函数）分块，不截断函数体，顶层初始化与导入一并覆盖。
- 多块可并行时，由主会话统一调度无会话历史的只读子代理（如 `fork_turns: "none"`）分块阅读，只传路径、适用约束、分配范围与返回要求，不传主会话推测；阅读子代理不写文档、不再派子代理。
- 每块返回已覆盖范围、职责、接口、约束、副作用、依赖、测试入口及已有文档冲突；汇总核对交叉依赖后，按“叶子模块 → 父级 → 根文档”顺序写入。
- 超时、失败或宿主并发受限时标明未覆盖缺口，可先交付轻量接入文档，不虚构未读模块的契约。
