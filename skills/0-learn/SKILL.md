# 0-learn

将已验证的经验收口到最合适的既有位置，避免零散 skill 泛滥与规则膨胀。本技能默认只提议不直接改文件，确认后再落盘。

## 0. 先判断是否值得沉淀

仅保留满足以下任一条件且**已经过实际验证**的内容：

- 用户明确纠正的偏好、约束或边界（如部署方式、目录/命名约定）。
- 试错后找到的根因解法（如环境/网络/工具链的特定坑及可靠绕过方式）。
- 后续会反复使用的稳定流程或防错检查。

一次性偶发问题、AI 已知常识、未验证的猜测 → 直接说明无需沉淀并停止。

## 1. 落点路由（优先收口）

按顺序匹配首个适用落点，**不轻易新建独立 skill**：

| 经验类型 | 权威落点 | 写法要求 |
| --- | --- | --- |
| 全局工具、CLI、环境排障、构建部署 | `https://github.com/Avlonjune7/0` 的 `skills/me-tools/SKILL.md` | 1–2 行精简条目；超 40–50 行时拆 `references/` |
| 全局 UI、设计系统、页面验收 | `https://github.com/Avlonjune7/0` 的 `skills/me-ui/SKILL.md` 或其 `references/` | 沿用现有路由结构 |
| 全局沟通风格、通用代码/Git 纪律 | 建议更新用户全局规则 | 说明建议改动，由用户决定 |
| 单项目架构约束、红线 | 项目根 `AGENTS.md` 或 `GEMINI.md` | 上游开源仓已有 `AGENTS.md` 时写 `GEMINI.md` 防冲突 |
| 单项目重大技术决定 | `docs/decisions.md` | 遵循 `0-setup` 追加格式，不改写历史 |
| 单项目稳定命令/发布步骤 | 项目脚本 + 根 `README.md` | 优先固化为脚本，不另建项目 skill |

仅当同时满足「跨项目高频复用 + 独立多步骤流程 + 放入 `me-*` 会明显臃肿或触发冲突」时，才提议新建独立 skill。

## 2. 去重与篇幅检查

- 提出修改前必须先读取目标文件：优先合并或修订已有条目，不机械追加重复内容。
- 检查目标文件是否接近单文件上限或已显臃肿；若是，先提议精简或拆 `references/`。
- 严禁写入真实密钥、域名、个人联系方式或项目敏感信息。

## 3. 提案与写入

1. 输出精简提案：列出每条经验的**目标文件、精确增删内容、选择该落点的理由**。
2. 等待用户明确确认（或删改意见）后再执行文件写入。
3. 写入后复核目标文件格式、无重复条目与无敏感信息；改动个人 skill（`me-*` / `0-*`）后直接提交推送到 `https://github.com/Avlonjune7/0`，无需同步本机 Agent 目录（由用户手动通过 cc-switch 同步）；单项目文档仍不自动提交或推送。
