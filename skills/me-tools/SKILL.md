# me-tools

## 工具选择

- 先复用项目已有命令和可用工具。查文档优先已有专用 CLI 或 Context7。临时 Python 环境按需用 `uv` 或 `uvx`。
- 大量日志、测试或差异输出可按命令支持情况用 RTK，保留退出码和关键错误。精确诊断或完整审查时读取原始输出。
- 对本次改动的脚本，优先复用已有检查。工具可用且与改动相关时，sh/bash 用 ShellCheck，PowerShell 用 PSScriptAnalyzer，GitHub Actions 用 actionlint。
- 缺少指定工具或技能时，优先用现有项目能力和对应版本的官方资料，说明实际验证缺口。安装依据用户授权或项目明确依赖。安装新技能时保留原版，已有同名技能先确认可否复用。修改已安装的技能须有明确授权。

反复手动执行的稳定步骤按需固化到已有脚本，并在项目 README 记录入口；环境正常且依赖配置未变时复用现有环境，跨环境可用性以实际检查为准。

## Windows 安装与 PATH

- 额外安装 CLI、开发工具和工具链优先用 WinGet。若支持自选目录，安装到 `D:\code\cli\<工具名>`。固定路径遵循工具约定，项目依赖跟随项目，已有安装按用户要求迁移。
- 命令找不到时，核对当前进程与用户、系统 PATH 的差异及目标工具的已知入口。常用工具目录为 `D:\code\cli`，WinGet 便携包也可能在 `D:\code\Portable\User`。仅定位目标工具，按需补充当前进程 PATH，保留宿主已有入口，然后核对命令解析到实际可执行文件。

## Go 构建与部署

- 本机开发和测试使用宿主目标。部署 Debian 时查明服务器架构，构建对应 Linux 产物。纯 Go 可交叉编译，涉及 CGO 时按项目依赖选兼容的工具链。目标平台变量仅在构建进程生效，部署后验证目标环境的实际运行。
