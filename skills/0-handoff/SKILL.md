# 0-handoff

交付一份可定位的交接文件和一段可粘贴到新会话的接续提示。本技能不新建会话，也不继续实施。

## 0. 先判断是否需要交接

按顺序判断，第一个"是"即为答案：

1. 下一步需要本会话的原始推理，且上下文还够用：**继续当前会话**。
2. 本会话内容对下一步没有用：**新开会话**即可。
3. 换工具、换目录或仓库、交给他人、分出支线任务：**交接**，继续本技能。
4. 任务能独立完成、无需用户盯着：**派子代理**。
5. 其他情况：**压缩上下文**（如 `/compact`，并说明下一步重点）。

结论不是交接时，给出建议后停止；用户坚持交接时照做。

## 1. 收集

- 以用户指定的下一步为重点，否则交接尚未完成的任务。复用会话中仍有效的结论，按需核实工作目录、分支、当前提交和未提交改动。无 Git 时记录目录与文件状态，不初始化仓库。
- 分清已确认决定、实施事实、待验证推测和未决问题。只记录实际运行过的验证，不为交接重跑仍有效的测试。

## 2. 保存

位置按优先级：用户指定 → 已有任务文档中的交接段（保留原有内容）→ Git 仓库内项目根 `.handoff/<日期>-<主题>.md`（未被忽略时追加到 `.git/info/exclude`，不改项目 `.gitignore`）→ 系统临时目录（无 Git 仓库时直接使用）。

按需记录：

- **目标与边界**：目标、AC、影响下一步的已确认决定。
- **工作位置**：绝对路径、分支、提交；worktree 路径；重要的未提交文件及归属。
- **已完成与证据**：结果、代码和文档位置、实际验证、尚未覆盖的部分。
- **剩余工作**：下一步、依赖、阻塞、需要用户决定的问题；不扩大既有授权。
- **运行状态**：只记录影响接续的服务、长任务和子代理的标识与归属；不假定它们已停止。

规格、计划、提交和报告用路径或 URL 引用，不复制全文。排除凭据、密钥和无关个人信息。

## 3. 交付

- 核对关键路径存在，状态与证据一致，未知项明确标注。
- 输出文件位置和接续提示：先读交接文件与项目指令，核对工作目录和现有改动，再继续剩余任务。按下一步建议一个技能（`$0-plan`、`$0-build`、`$0-review`、`$0-setup`），不自动调用。
- 交给独立审查时，只提供原始需求、版本范围和必要来源，不带本会话的推测和结论。
- 有值得写进 `AGENTS.md` 的教训时提 1 条建议。
- 说明新会话不会继承完整历史，如实说明其他仍在运行的会话或代理。保存完成即停止。
