# 0-handoff

交付一份可定位的交接记录和可直接粘贴到新聊天的接续提示。本技能整理任务状态，不自动新建聊天或继续实施。

## 确定接续目标

以用户指定的下一步为重点；未指定时交接当前尚未完成的任务。复用会话中仍有效的结论，按需核实实际工作目录、分支、当前提交和未提交改动。无 Git 时记录目录与文件状态，不初始化仓库。

区分已确认决定、实施事实、待验证推测和未决问题。记录已运行的验证及适用版本，不把计划执行的检查写成通过，也不为交接重复运行仍有效的测试。

## 保存交接

用户指定位置优先。已有当前任务文档时，在其中更新简短交接段，保留原有需求和人工说明；否则写到系统临时目录下的唯一 Markdown 文件。不要仅为交接新建整套项目文档。

按实际需要记录：

- **目标与边界**：当前目标、验收条件，以及影响下一步的已确认决定。
- **工作位置**：实际目录、分支与提交；独立 worktree 的准确路径；未提交或未跟踪的重要文件及已知归属。
- **已完成与证据**：结果、相关文档和代码位置、实际验证及尚未覆盖的部分。
- **剩余工作**：下一步、真实依赖、阻塞和需要用户决定的问题；不要把既有授权扩展到新范围。
- **运行状态**：只有会影响接续的服务、长任务或子代理才记录状态、标识和归属；不能假定它们已停止或会随新聊天迁移。

已有规格、计划、提交和报告用路径或 URL 引用，不复制全文。跨目录交接使用绝对路径；临时文件注明位置。排除凭据、密钥和无关个人信息。

## 交付与接续

核对关键路径存在、状态与证据一致，未知项明确标注。输出文件位置及一段接续提示：先读取交接记录与适用项目指令，核对工作目录和现有改动，再继续剩余任务。

按下一步建议一个适合的技能，例如方案用 `$0-plan`、实施用 `$0-build`、审查用 `$0-review`、文档核对用 `$0-sync`；不自动串联调用。不必重新运行 `$0-setup`。

若下一窗口用于独立审查，交付原始需求、版本范围和必要来源，不把本会话推测或既有审查结论作为审查前提。若用于接续开发，则保留影响实施的已确认决定和排查证据。

记录已保存且接续提示可用后停止本次工作。说明新聊天不会自动获得完整历史；其他仍在运行的会话或代理是否停止须如实说明，不宣称已经停止它们。

方法参考 Matt Pocock 的 handoff；按 0 工作流的任务记录与手动触发约定适配。
