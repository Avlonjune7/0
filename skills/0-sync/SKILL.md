# 0-sync

## 确定范围与授权

先读适用的项目指令和 `docs/workflow.md` 或等效约定。按用户指定的文档、模块或变更确定范围，未指定路径时从当前项目定位。复用已有 README、PRD、ARCHITECTURE、PLAN 及项目约定的权威位置，缺少工作流文档时按现状继续。涉及 UI 时读取根 `DESIGN.md`，按其适用范围核对。

检查、一致性核对和漂移报告请求只读。同步或修订请求授权原地修正文档中证据充分的现状描述。需要写入的内容限于文档，发现实现缺漏时报告对应代码位置。仅按用户要求保存独立报告。

## 核对证据与覆盖

列出范围内的文档、适用版本和对应实现入口。按文档用途区分已认可要求、现状说明、草案和历史记录。项目已有规格与任务位置优先，默认 `docs/specs` 保存长期认可的行为，`docs/tasks` 记录某次任务。任务状态只按已有记录与可核实的完成证据更新。

从文档的路径、符号和断言追到具体实现，读取相关入口、调用路径、配置、Schema 或测试。核对写出的职责、接口、约束、副作用、命令等仍成立，也从实现反查文档承诺覆盖的范围，查找遗漏的关键行为。区分环境配置、代码可证行为和已实测结果。每份文档都应能对应到已核对的章节或模块，查不到的证据记作覆盖缺口。

## 处理差异

- **说明过期**：有明确证据时按授权更新具体段落，保留人工说明、历史版本和无关修改。重复内容优先指向现有权威来源，生成文档按项目已有流程处理。
- **实现与认可要求冲突**：保留要求，记录预期、实际和双方证据位置。使用同样方式处理根 `DESIGN.md` 与现有 UI 的冲突。变更认可要求须有用户明确决定。
- **草案、冲突或证据不足**：保持原有状态，注明未决事项和待核查依据，完成其余可确认部分。若现状说明与认可要求并存且确需同步说明，明确差异仍待处理。

## 验证与交付

核对范围内文档及其内部链接，修订时确认修改后链接路径和锚点有效；检查本地路径和常见标题锚点优先使用 [check_links.py](scripts/check_links.py)（`--help` 查看参数）。尚未建立的目标用文字说明。用 diff 核验修改段落与证据一致，变更限于授权的文档并保留他人编辑。相同范围和证据再次运行时，现有内容已成立就直接交付结论，避免重写段落、刷新时间戳或追加重复报告。

交付检查范围、已修订项、仍存在的差异与证据，以及未覆盖的部分。一致部分仅给出覆盖范围摘要，详细清单聚焦差异、冲突与缺口，不逐项复述一致内容；区分已核对的配置与实际执行的验证。
